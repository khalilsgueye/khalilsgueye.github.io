Docker Content Publisher

An automated pipeline that turns raw text notes into fully formatted, published pages on my portfolio site — no manual HTML or copy-pasting required.

PythonAnthropic APIGitHub REST APIDockerAutomation

How it works

01

Watch the inbox

The agent scans a designated inbox folder for new text files, each one representing a piece of content to publish.

02

Detect content type

A filename prefix — blog, writeup, or portfolio — tells the agent what kind of content it is and which part of the site it belongs on.

03

Clean and structure with Claude

The raw text is sent to Claude along with a type-specific prompt that rewrites the content and structures it into a title, summary, tags, and body.

04

Generate a matching HTML page

The structured output is used to build a full HTML page that follows the site's existing design system, so new content looks native to the site.

05

Publish directly to GitHub

The new page and an updated listing/index page are committed straight to the GitHub repo using the Contents API — no manual edits.

06

Handle failures gracefully

If a file fails due to bad formatting or an API error, it stays in the inbox for the next run while the rest of the batch still processes and successfully published files move to a processed subfolder.

Applied uses

This project removes the tedious part of publishing: turning a rough note into a polished, live web page.

  • Personal blogging pipeline. Drop a text file in a folder and have it appear as a fully formatted blog post without touching HTML.
  • Portfolio maintenance. Add new project writeups or portfolio entries without manually editing index pages or matching site styling by hand.
  • Batch content processing. Multiple files can be processed in one run, with failures isolated so one bad file doesn't block everything else.
  • Path to full automation. Being containerized with Docker means this can eventually run on a schedule or trigger, publishing content unattended.
